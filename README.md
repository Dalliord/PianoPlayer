# Piano Player

Windows-плеер фортепианных партитур: интерфейс на Python/PySide6, физические клавиатурные события через AutoHotkey v2. Работает с совместимым виртуальным пианино в активном окне.

Библиотека и редактор находятся слева, три настройки тайминга — справа, управление воспроизведением — внизу. Описания песен и кнопка сведений о пресете удалены. Кнопка «Пресет песни» восстанавливает исходный тайминг выбранной песни.

**Добавить песню** открывает окно с названием и текстом партитуры. Перед добавлением проверяются название, синтаксис и наличие нот. Новая песня получает текущие значения трёх настроек, сохраняется в `data/library` и появляется в списке. Её дальнейшие правки и тайминг сохраняются независимо от остальных песен. Одинаковые названия допустимы: записи имеют разные идентификаторы.

**Корзина** справа от списка удаляет выбранную песню из библиотеки, включая встроенные песни и MIDI. Удаление сохраняется после перезапуска. Появившаяся рядом кнопка **Отменить удаление** возвращает последнюю удалённую песню вместе с её правками и таймингом; отмена доступна до закрытия приложения. Во время воспроизведения, паузы и обратного отсчёта эти кнопки заблокированы. Можно удалить все песни и затем добавить новые. Исходные файлы сохраняются, список удалённых песен записывается в `data/settings.json`.

**Язык** выбирается в верхней панели и меняется сразу. Доступны Русский, English, Español, Português, 日本語, 한국어, 中文, Français и Deutsch, каждый со своей иконкой флага. Выбор сохраняется после перезапуска. Названия песен и текст партитуры не переводятся.

Кнопка **Импорт MIDI** добавляет локальные `.mid`/`.midi` отдельными песнями: с выбором дорожек, учётом смен темпа, длительностей и педали sustain. Перед сохранением показаны изменения диапазона и конфликтующих клавиш. Исходный MIDI не меняется.

Во встроенной библиотеке оставлены только:

| Песня | Note Delay | Key Hold Time | Start Delay |
|---|---|---|---|
| BEASTARS -pf solo- | 300 ms | 200 ms | 3.0 s |
| Mr. Sandman | 300 ms | 200 ms | 3.0 s |
| Until We Reach the Dawn | 75 ms | 150 ms | 3.0 s |
| Wild Side — Piano | 20 ms | 100 ms | 3.0 s |
| Rush E (Full Version) | 117 ms | 90 ms | 3.0 s |

Старые записи выведены из активного каталога; архив метаданных находится в `assets/songs/archive`, нотные файлы сохранены для истории и проверок.

В sheet доступны точный интервал `|delay=75.5|`, абсолютная пауза `|wait=250|`, темп `|bpm=120|`, триоли `|step=1/3|` и плавный переход `|ramp=180,8|`. `|reset|` возвращает базовый Note Delay. Явные команды имеют приоритет над полями настроек. Справка открывается под редактором; подробности — в [docs/timing-and-midi.md](docs/timing-and-midi.md).

Партитуру можно редактировать, заменять вставкой своего sheet, открывать и сохранять в UTF-8 `.txt`. Кнопка **Оригинал** возвращает исходный текст выбранной песни.

## Установка и запуск

Требования: Windows 10/11 x64, [Python 3.12+](https://www.python.org/downloads/windows/) и [AutoHotkey v2](https://www.autohotkey.com/). При установке Python включите **Add python.exe to PATH**. AHK v1 не подходит.

Для обычного запуска откройте **run.bat**. При первом запуске он проверит библиотеки и, если их нет, создаст локальное окружение `.venv`, установит зависимости и откроет приложение. Первая установка требует интернета и может занять несколько минут. Повторные запуски используют установленные библиотеки. AutoHotkey v2 устанавливается отдельно.

Установка вручную:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Без виртуального окружения:

```powershell
pip install -r requirements.txt
python main.py
```

После установки запускайте двойным щелчком по `run.bat` или ярлыку **Piano Player** в рабочей папке приложения. В репозиторий включены исходники; Python и библиотеки не поставляются внутри скачанного архива.

`run.bat` использует Python из `.venv` или установленный Python 3.12+ через `py`/`python`. `launcher.py` проверяет зависимости тем же интерпретатором, которым запускает приложение. Локальные библиотеки из `.deps`, если они есть, подхватываются автоматически. Для проверки установки без открытия окна выполните `run.bat --setup-only`.

При публикации через веб-интерфейс GitHub загружайте только исходные файлы. Папки `.venv`, `.deps`, `__pycache__`, `data` и `logs`, появившиеся после локального запуска, загружать не нужно.

## Три основных настройки

| Параметр | Диапазон | Пресет BEASTARS | Назначение |
|---|---|---|---|
| Note Delay | 20–500 ms | 300 ms | Интервал между началами обычных нот и аккордов; длительность одного `-` |
| Key Hold Time | 5–200 ms | 200 ms | Базовое время от DOWN до UP для ноты и клавиш аккорда |
| Start Delay | 0–10 s, шаг 0.1 | 3.0 s | Время для переключения на пианино после Play |

В `{...}` интервал между началами нот автоматически равен **Note Delay × 0.35**: при 100 ms получаем 35 ms. После последней ноты группы до следующего события используется обычный Note Delay. Отдельных Chord Hold, Fast Sequence Delay, Pause Duration и Speed Multiplier нет.

Удержание не прибавляется к интервалу: при Note Delay = 100 ms и Key Hold Time = 35 ms ноты `abc` начинаются в 0, 100 и 200 ms. Если удержание длиннее интервала, разные клавиши могут перекрываться. Повтор той же физической клавиши отпускает предыдущий нажим и начинает новый: клавиатура не может удерживать два независимых нажима одной клавиши одновременно.

Для отдельных мест укажите длительность прямо в sheet, сразу после ноты или группы:

```text
[asd]<1000> f g h
```

Здесь `a`, `s`, `d` удерживаются **1000 ms**, пока `f`, `g`, `h` продолжают играть с обычным Note Delay. При Note Delay 100 ms аккорд начинается в 0 ms, следующие ноты — в 100, 200 и 300 ms. Для одной ноты используйте `a<1500>`; для `{asdf}<500>` каждая нота быстрой группы получает удержание 500 ms. Пробела перед `<…>` нет, внутри — целое число **5–60000 ms**. Без этой пометки используется обычный Key Hold Time; дополнительных полей настройки нет. Явная длительность задана в миллисекундах и не зависит от Note Delay. У нескольких нот и аккордов могут быть разные сроки отпускания; проигрыватель дожидается окончания удержаний. Повтор одной клавиши переигрывает только её, остальные удерживаемые клавиши аккорда продолжают звучать.

Внутри аккорда можно указать разные удержания: `[a<1000>s<200>d<500>]` нажимает три клавиши одновременно и отпускает каждую в своё время. Общая пометка после группы задаёт длительность остальным клавишам: `[a<1000>sd]<300>` удерживает `a` одну секунду, а `s` и `d` — 300 ms. Это также работает внутри `{…}`, сохраняя последовательные начала нот.

Переключатель **Очеловечивание** включён по умолчанию и сохраняется между запусками. Он добавляет небольшие отклонения начала нот от сетки: до 6% Note Delay, максимум 10 ms. Удержания немного различаются — до 7% базового времени (для коротких удержаний используется диапазон до 2 ms), в пределах 5–200 ms. Аккорды распределяются на 2–3 близкие группы с общим разбросом до 6 ms. В быстрых местах отклонения и разброс сокращаются, чтобы сохранить порядок нот. При каждом Play получается новая вариация.

Явно записанные удержания `<…>` сохраняют указанную длительность и с включённым очеловечиванием. На паузе все клавиши отпускаются; Resume восстанавливает оставшееся время их удержания. Stop и F8 немедленно отпускают клавиши и отменяют восстановление. MIDI и WAV при экспорте также учитывают индивидуальные длительности.

Очеловечивание сохраняет общую длительность, положения пауз и структуру партитуры: отклонения рассчитываются от абсолютных отметок и не накапливаются к концу песни. Стартовый отсчёт не меняется. Переключатель блокируется на время воспроизведения; числовых параметров по-прежнему три. Выключите его для точного воспроизведения исходной сетки.

Модификаторы устанавливаются отдельно для каждой группы клавиш одного регистра внутри аккорда. В `[ejTu]` клавиши `e`, `j`, `u` нажимаются без Shift, а `T` — с Shift. При выключенном очеловечивании все DOWN-события аккорда отправляются одним пакетом, без Note Delay между ними, и клавиши остаются зажаты вместе. При отпускании используется тот же регистр, что при нажатии: это предотвращает зависание клавиш в браузерном пианино. Следующая строчная нота снимает Shift, даже если предыдущая клавиша ещё удерживается; удержания самих клавиш сохраняют независимые сроки.

Для BEASTARS -pf solo- проверенный пресет: **300 ms / 200 ms / 3.0 s**. Интервал 300 ms подтверждён в исходном коде проигрывателя PlayPianoSheets; удержание 200 ms выбрано по проверке пользователя на этой песне. Поля тайминга увеличены, значения можно менять вручную. Изменения применяются при следующем Play и сохраняются отдельно для каждой песни, вместе с отредактированным sheet. Повторный выбор песни и новый запуск приложения сохраняют пользовательские изменения. Кнопка **Пресет песни** возвращает её исходные тайминги, сохраняя отредактированный текст. Настройки хранятся в `data/settings.json`. Повреждённые настройки восстанавливаются.

Сами символы sheet не содержат достаточной информации для определения оптимального темпа и удержания. Для будущих песен сначала проверяется тайминг источника и реальное воспроизведение; происхождение пресета записывается в `timing_basis` каталога. Порядок проверки описан в `docs/preset-calibration.md`.

## Использование

1. Выберите песню из списка: партитура и сохранённые настройки загрузятся автоматически. При первом выборе используется собственный пресет песни.
2. Откройте совместимое виртуальное пианино в браузере. При необходимости выберите свободную игру и **Transpose 0**.
3. Нажмите **Играть** (в английском интерфейсе — **Play**).
4. Во время обратного отсчёта переключитесь в браузер и нажмите на область пианино, чтобы клавиатурный ввод попадал в него. При Start Delay = 0 обратный отсчёт пропускается.
5. Следите за прогрессом и текущим участком партитуры. F6 ставит на паузу и продолжает; F7 останавливает, F8 выполняет аварийную остановку.

Выбор другой песни и редактирование текста блокируются на время обратного отсчёта, воспроизведения и паузы. После Stop снова можно выбирать песню и редактировать sheet. Список определяется `assets/songs/catalog.json`, каждый элемент включает собственные значения трёх параметров, сведения об их проверке и встроенный sheet.

Синтаксис:

```text
abc          последовательные ноты
[asd]        одновременный аккорд
{asdf}       быстрая последовательность с интервалом 35% от Note Delay
--           пауза на два Note Delay
[f-8][d-e]   дефис внутри группы — клавиша, а не пауза
```

Пробелы, табуляция и переносы строк служат форматированием. Регистр важен: `A` и `!` требуют Shift. Используется физическая карта US-клавиатуры независимо от активного языка ввода Windows. Поддерживаются печатные ASCII-символы; скобки зарезервированы для синтаксиса групп. Вложенные и пустые группы запрещены.

## Управление

- **F6** — Play / Pause / Resume.
- **F7** — Stop, включая обратный отсчёт.
- **F8** — Emergency Stop: отмена сессии и отпускание клавиш.
- Кнопки **Play**, **Pause / Resume**, **Stop** выполняют те же действия.

Глобальные горячие клавиши работают, пока запущен AHK worker. В настройках их можно заменить другими функциональными клавишами. Пауза отпускает удерживаемые клавиши; Resume восстанавливает оставшиеся удержания и продолжает с ближайшего ещё не начатого события. Для новой сессии сначала нажмите Stop.

Воспроизведение отправляет клавиши в текущее активное окно. Привязки к запущенному Roblox, проверок процесса и автоматической паузы при смене фокуса нет: приложение подходит для проверки на PlayPianoSheets в браузере. Старые настройки ограничений Roblox удаляются при загрузке.

В **Advanced** доступны путь к AHK v2, Send Mode (Event / Input) и горячие клавиши. Изменения перезапускают worker. Музыкальных настроек и ограничений процесса в Advanced нет.

## Частые проблемы

- **AutoHotkey v2 не найден**: установите v2 или укажите `C:\Program Files\AutoHotkey\v2\AutoHotkey64.exe` в Advanced.
- **No module named PySide6**: запускайте `run.bat`, чтобы он установил библиотеки. Для ручной установки используйте `.venv\Scripts\python.exe -m pip install -r requirements.txt`.
- **Пианино не принимает клавиши**: активируйте область пианино в браузере и попробуйте другой Send Mode. Для Shift-символов на сайте используйте английскую раскладку Windows и выключите Caps Lock.
- **Красные ноты на `[ejTu]` / `[dEuw]`**: установите свежую версию приложения и перезапустите его; обработка Shift теперь сохраняет регистр каждой клавиши при DOWN и UP. На сайте нажмите Reset перед повторной проверкой.

Журнал: `logs/app.log`. Тайминг использует абсолютные отметки `QueryPerformanceCounter`; системное разрешение таймера восстанавливается после завершения, паузы или остановки. Реальная точность зависит от планировщика Windows и обработки ввода игрой.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Основные тесты parser, playback plan, song library, humanization и settings не запускают AHK и не отправляют клавиши. Проверки очеловечивания контролируют сохранность нот, порядок быстрых последовательностей, разброс аккордов, диапазоны удержаний и неизменную пятиминутную длительность с паузой перед дропом. Интеграционные тесты worker используют только паузы, а тесты аккордов и удержаний записывают события через заглушку: физические key-down события не отправляются. Для приёмочного теста выберите BEASTARS -pf solo-, переключитесь на пианино в браузере и проверьте воспроизведение, Pause/Resume, F7 и F8.

Дополнительные проверки, при установленных PySide6 и AHK v2:

```powershell
$env:RUN_AHK_TESTS = "1"
$env:RUN_QT_TESTS = "1"
python -m unittest discover -s tests -v
```

Qt-тесты запускают интерфейс в offscreen-режиме, проверяют каталог, пресеты, редактирование и восстановление sheet, сохранение текста и таймингов между запусками, размер трёх полей, диапазоны, блокировку Play при ошибках, обратный отсчёт и его отмену. AHK-тест восстанавливает символы из каждого события с учётом Shift и проверяет DOWN/UP проблемных `[ejTu]` и `[dEuw]`, общий пакет аккорда и удержание 200 ms. Полный каталог дополнительно проигрывается в записывающий тестовый обработчик при обычном темпе и с перекрывающимися удержаниями: проверяются все символы, точные сроки отпускания, отсутствие конфликтов физических клавиш и зависших модификаторов. Физического ввода в этих тестах нет. Планы временно хранятся в `data/sessions/` и удаляются после остановки, завершения или закрытия приложения.
